# Обновление ачивок («обнови ачивки»)

Точная процедура для сессии Claude, когда Геннадий пишет «обнови ачивки». Коротко — в `CLAUDE.md`,
здесь — всё целиком: правила приватности, шаги, команды, форматы файлов и типичные случаи.

Два скрипта:

- `npm run sync` — находит в папке достижений файлы, которых ещё нет на сайте, и готовит их к ревью
  в `.private/inbox/<sha12>/` (превью, OCR, кандидаты на закраску, черновик записи); ведёт манифест.
- `npm run media` — делает из исходника публичную картинку с закрашенными личными данными.

Оба работают только на ПК Геннадия (там лежит папка достижений и есть Windows OCR). Сборка сайта
и GitHub Actions их не запускают: сайт берёт уже готовые `content/achievements/media/<id>.webp`.

## 1. Правила приватности (без исключений)

Никогда не попадают на сайт, в репозиторий, в коммиты, в сообщения и в манифест:

| Что | `kind` в redact | Как поступаем |
| --- | --- | --- |
| ИИН / ЖСН (12 цифр) | `iin` | закрасить |
| Номера документов, сертификатов, регистрации, бланков, Credential ID, ссылки проверки (`coursera.org/verify/…`, `cert.efset.org/…`) | `doc-number` | закрасить |
| QR-коды и штрих-коды документов | `qr` | закрасить целиком (штрих-коды детектор не ищет — смотри глазами) |
| Телефоны | `phone` | закрасить |
| Чужие e-mail (и свой — тоже, контакты на сайте отдельно) | `email` | закрасить |
| Даты рождения | `birth-date` | закрасить |
| Адреса | `address` | закрасить |
| Оценки, баллы, GPA, проценты, таблицы оценок | `grade` | закрасить строки целиком; если оценки — весь смысл документа, скрыть файл (`grades`) |
| Личные документы (удостоверение, паспорт, свидетельства) | — | не публиковать: `--hide … --reason personal-doc` |

Ещё:

- Закраска — только сплошная (`#16181b`), никогда не размытие; её делает `npm run media`, вручную картинки не правим.
- Имена исходных файлов могут содержать ИИН: не пиши их в контент, коммиты, манифест и сообщения. Ссылайся на файл по `sha12`.
- Папка достижений (`C:\Dad\*chievements`, первая «А» кириллическая) — только чтение: ничего не переименовывать, не перемещать, не удалять.
- `.private/` никогда не коммитится (он в `.gitignore`). Не копируй оттуда ничего в `content/`, кроме выверенных фактов.
- Факты (название, организатор, дата, место, результат) — только из документа. Непонятно — спросить Геннадия.
- Без ярлыков: не «разработчик», «спортсмен», «специалист» — описываем, что сделано.
- Чужой документ или проект, сделанный для другого человека, — не публикуем (`not-mine`), при сомнении — `ask`.

### Коды причин (`--reason`)

| Код | Когда |
| --- | --- |
| `not-mine` | документ другого человека (сестры, друга, ученика) |
| `personal-doc` | личный документ: удостоверение, паспорт, справка, свидетельство |
| `grades` | документ про оценки (транскрипт, ведомость, приложение к диплому) |
| `duplicate` | та же ачивка уже есть на сайте из другого файла (скан и фото одного диплома, PDF и JPG) |
| `not-achievement` | не достижение: билет, квитанция, расписание, письмо, черновик |
| `low-value` | достижение есть, но слишком мелкое для сайта (участие «для галочки») |
| `photo` | просто фотография без документа (если фото само по себе ценно — это решение Геннадия) |
| `ask` | непонятно — спросить Геннадия; в отчёте перечислить такие файлы |
| `test` | тестовые прогоны и пробные файлы |

`--note "…"` пишется только в приватный `.private/ledger.json`: там можно человеческими словами
(«диплом сестры», «то же, что 2025-hackathon-x, но фото»). В публичный манифест попадает только код.

## 2. Процедура

### 0. Подготовка

```bash
git pull
git status            # рабочая копия чистая? Чужие незакоммиченные правки — не трогать
npm run sync -- --status
```

### 1. Найти новое

```bash
npm run sync
```

Для каждого нового файла (SHA-256 нет в `content/.sync/manifest.json`) появится папка
`.private/inbox/<sha12>/`, а сам файл попадёт в манифест как `pending`. В конце — сводка: папка
инбокса, число страниц, найденные виды данных, подсказки со страницами («стр. 26: есть оценки»,
«похоже на личный документ») и неподдерживаемые файлы. Неподдерживаемые (не pdf/jpg/jpeg/png/webp/docx/pptx) — сказать
Геннадию, что их надо сконвертировать; HEIC — «сконвертируй в JPG».

Время: ~2–4 с на страницу (рендер + Windows OCR в 2 процесса + QR); весь архив (90 файлов, 178 стр.)
с нуля — ~7 мин. Повторный запуск берёт превью и OCR из кэша инбокса: после правок детектора
`npm run sync -- --scan-only --all` пересчитывает кандидаты, review и черновики всех файлов за ~5 мин.
Долгие прогоны запускай в фоне и не параллель с другими тяжёлыми задачами (память ПК общая).

### 2. Посмотреть каждую страницу

Для каждой папки инбокса **открой Read-ом** `page-N.png` (оригинал) и `review-N.png` (кандидаты в цветных
рамках с номерами `#n kind`; номер = порядок в `candidates.json` и в `redact` черновика). Сверь:

- всё ли приватное в рамках (см. таблицу выше) — детектор ошибается, глаза важнее;
- не попали ли в рамки название, ФИО, организатор, дата выдачи — такие пункты из redact убрать;
- что это за документ и чей он.

Текст страницы (с замаскированными ИИН/номерами) — в комментариях `draft.md`. Многостраничный файл
(скан-подборка грамот) смотри постранично: на каждой странице может быть своя ачивка.

### 3. Решить: публикуем или скрываем

- Не публикуем → `npm run sync -- --hide <sha12> --reason <код> [--pages 3] --note "почему"`.
- Публикуем → шаг 4. В одном файле может быть несколько ачивок (по странице на каждую) и страницы,
  которые скрываем, — тогда `--link`/`--hide` с `--pages` для каждой части.

### 4. Написать запись

Скопируй `draft.md` в `content/achievements/<id>.md`:

- `id` — `yyyy-коротко-латиницей` (`2025-hackathon-x`, `2024-math-olympiad`): год с документа, латиница, дефисы.
- Все текстовые поля `{ ru, en }`: `title` (что и где, коротко), `event`, `issuer`, `result`, `description` (1–2 предложения),
  `imageAlt`. Факты — только из документа. Перевод названий — аккуратный, официальное английское название, если оно есть на документе.
- `date` — как на документе: `YYYY`, `YYYY-MM` или `YYYY-MM-DD`.
- `category`, `level` — из списка в `src/content.config.ts` (черновик подсказывает category по словам, но проверь).
- `podium: true` — призовое место, победа, финал. `featured: true` — только 8–10 сильнейших на весь сайт.
- `project: <id>` — если ачивка про проект из `content/projects`.
- `source: [{ sha256: "<полный хэш>", pages: "1" }]` — страница(ы) этой ачивки. `npm run media` публикует первую страницу из `pages`.
- Комментарии черновика (OCR-текст) из записи **удалить** — в репозиторий не должно уйти ничего, кроме фактов.

Файлы, начинающиеся с `_`, сборка игнорирует — так можно оставить себе черновик, но лучше держать черновики в `.private/`.

### 5. Проверить redact

`redact` в черновике — все кандидаты детектора. Оставь те, что действительно приватные, удали
ложные (название, имя), **добавь** пропущенные. Координаты — доли страницы (0..1, от левого верхнего угла,
до `crop`):

```bash
npm run sync -- --boxes <sha12> --page 1                 # все строки страницы с координатами
npm run sync -- --boxes <sha12> --page 1 --grep "№"      # готовые пункты redact для найденного текста
```

Пиксели из `ocr-N.json` / `text-N.json` делятся на `width` / `height` из того же файла. Для QR и
печатей бери рамку с запасом. Для фото документа на столе добавь `crop: { x, y, w, h }` (тоже доли
исходной страницы). `kind` в redact — для справки (`iin`, `doc-number`, `qr`, `grade`, … или `private`).

### 6. Сделать картинку и посмотреть её

```bash
npm run media -- --id <id>
```

Открой `content/achievements/media/<id>.webp` **Read-ом**. Не должно быть видно ни одной цифры
ИИН/номера, ни кусочка QR, телефонов, адресов, оценок. Видно — поправь redact и повтори. `media`
добавит в запись `image: ./media/<id>.webp`, если его не было, и предупредит, если QR/ИИН/телефон
из `candidates.json` остался не закрыт.

### 7. Записать решение в манифест

```bash
npm run sync -- --link <sha12> --entry <id> [--pages 1-2]
npm run sync -- --hide <sha12> --reason <код> [--pages 3] [--note "…"]    # для остальных страниц, если есть
```

`--link` проверяет, что `content/achievements/<id>.md` существует. Страницы, не привязанные и не
скрытые, остаются `pending`.

### 8. Общая проверка

```bash
npm run media -- --check      # нет картинки/исходника, не закрыт QR/ИИН, redact пуст при кандидатах, нет --link, остался текст черновика
npm run sync -- --status      # ничего не осталось «ждёт решения» без причины
npm run build                 # должен пройти без ошибок
```

### 9. Опубликовать

Коммитим только: `content/achievements/<id>.md`, `content/achievements/media/<id>.webp`,
`content/.sync/manifest.json` (и правки проектов/профиля, если были). Перед коммитом — `git status` и
`git diff --cached`: ни путей `C:\…`, ни имён исходных файлов, ни OCR-текста.

```bash
git add content/
git commit -m "Add achievement: <id>"          # без имён исходных файлов
git push
gh run watch                                    # или: gh run list --limit 1
```

Дождись зелёной сборки (~2–3 мин), открой `https://gennadiy0041.github.io/#a-<id>` (и `/en/#a-<id>`):
карточка на месте, картинка в лайтбоксе закрашена, тексты RU/EN верные.

### 10. Отчитаться Геннадию

Коротко: что добавлено (id, название), что скрыто и почему (коды), какие файлы `ask` — вопросы к нему,
какие файлы не поддерживаются.

## 3. Справочник команд

### `npm run sync`

| Команда | Что делает |
| --- | --- |
| `npm run sync` | новые файлы → инбокс + манифест (`pending`) |
| `npm run sync -- --scan-only` | то же без записи в манифест |
| `npm run sync -- --scan-only --all` | заново все файлы папки (первичный импорт, после правок детектора) |
| `npm run sync -- --only <sha12\|путь>` | только этот файл (можно повторять); `--force` — заново рендер и OCR |
| `npm run sync -- --status [--json]` | все источники: sha12, страницы, статус/запись/причина, путь (только в консоль) |
| `npm run sync -- --link <sha12\|путь> --entry <id> [--pages 1-2] [--note "…"]` | привязать страницы к записи |
| `npm run sync -- --hide <sha12\|путь> --reason <код> [--pages …] [--note "…"]` | скрыть страницы с причиной |
| `npm run sync -- --forget <sha12\|путь>` | убрать файл из манифеста (и его заметки); следующий sync снова сочтёт его новым |
| `npm run sync -- --boxes <sha12\|путь> [--page N] [--grep "текст"]` | строки страницы с координатами 0..1 |

`<sha12>` — первые ≥ 6 символов хэша (имя папки инбокса). `--pages`: `3`, `1-2`, `1,3,5-7`, `all`.
Для тестов: `--manifest <файл>`, `--content-dir <папка>`, `--source <папка ачивок>`, `--private-dir <папка вместо .private>`.
Папка ачивок: `--source`, иначе `$ACHIEVEMENTS_DIR`, иначе первая `C:/Dad/*chievements`.

### `npm run media`

| Команда | Что делает |
| --- | --- |
| `npm run media` | новые картинки и те, у которых поменялись source / page / redact / crop (учёт в `.private/media-cache.json`) |
| `npm run media -- --id <id>` | только эта ачивка, рисуется заново (можно повторять) |
| `npm run media -- --all` | перерисовать всё |
| `npm run media -- --check` | только проверка, ничего не пишет; код выхода 1, если есть проблемы (в т.ч. в записи остались комментарии из `draft.md`) |

Для тестов: `--content-dir`, `--source`, `--private-dir`.

Как рисуется: страница `source[0].pages` (первая из списка, по умолчанию 1) рендерится в ~300 dpi
(длинная сторона ≤ 4000 px), каждый redact этой страницы расширяется на 0,4 % и заливается `#16181b`
со скруглением ~6 px, затем `crop`, уменьшение до 1800 px по длинной стороне, WebP q82 без метаданных.

## 4. Файлы

### Публичный манифест `content/.sync/manifest.json` (коммитится)

Только хэши и решения — **никаких имён файлов, путей и текста**:

```json
{
  "version": 1,
  "files": {
    "<sha256>": {
      "ext": "pdf",
      "pages": 23,
      "firstSeen": "2026-11-16",
      "items": [
        { "pages": "1-2", "status": "entry", "entry": "2025-hackathon-x" },
        { "pages": "3", "status": "hidden", "reason": "duplicate" },
        { "pages": "4-23", "status": "pending" }
      ]
    }
  }
}
```

`status`: `entry` (на сайте, `entry` = id записи), `hidden` (с `reason`), `pending` (ждёт решения).
Одна страница может кормить несколько записей; скрытие снимает страницу со всех записей (с предупреждением).
Идентичность файла — SHA-256 байтов: копия в другой папке — тот же источник; изменённый файл — новый источник.

### Приватное (`.private/`, не коммитится)

| Файл | Что внутри |
| --- | --- |
| `sources.json` | sha256 → `{ path, rel, size, mtime, ext, pages, also }` — где файл лежит на этом ПК; обновляется каждым запуском |
| `ledger.json` | sha256 → `{ notes: [{ date, pages, status, entry?, reason?, text }] }` — заметки `--note` |
| `inbox/<sha12>/page-N.png` | страница, ~150 dpi, ≤ 2400 px |
| `inbox/<sha12>/ocr-N.json` | Windows OCR: `{ width, height, lang, lines: [{ text, x, y, w, h, words: [...] }] }`, пиксели `page-N.png` |
| `inbox/<sha12>/text-N.json` | текстовый слой PDF (если есть) в том же формате |
| `inbox/<sha12>/candidates.json` | `{ candidates: [{ page, x, y, w, h, kind, masked, confidence, from }], findings, hints }` — сырых значений нет |
| `inbox/<sha12>/review-N.png` | страница с рамками кандидатов |
| `inbox/<sha12>/redacted-N.webp` | страница, где закрашены все кандидаты (как выглядело бы без ревью) |
| `inbox/<sha12>/draft.md` | черновик записи + OCR-текст с маской в комментариях |
| `inbox/<sha12>/meta.json` | версия рендера, размеры страниц — для кэша |
| `media-map.json` | картинки проектов/профиля для `npm run media` (ниже) |
| `media-cache.json` | картинка → отпечаток входных данных, из которых она нарисована |

`media-map.json`:

```json
[
  { "out": "content/projects/media/<project>/cover.webp", "src": "C:/…/file.pdf", "page": 1,
    "crop": { "x": 0, "y": 0.1, "w": 1, "h": 0.6 }, "redact": [{ "page": 1, "x": 0.7, "y": 0.05, "w": 0.2, "h": 0.04 }],
    "max": 2000, "quality": 82 }
]
```

`out` — внутри проекта, `.webp`; `src` — абсолютный путь (или от корня проекта); `page`, `crop`, `redact`, `max`, `quality` — необязательны.

## 5. Детектор: что ищет и чего не умеет

Источник текста — Windows OCR (`scripts/lib/winocr.ps1`, язык ru, 2 процесса, таймаут 60 с) и, для PDF
с текстом, текстовый слой mupdf (точнее OCR, кандидаты объединяются). Строки на одной высоте
склеиваются в «ряды», чтобы метка в одной ячейке находила значение в соседней.

- **ИИН** — 12 цифр подряд (можно группами через пробел), с меткой ИИН/ЖСН/IIN; проверяется контрольная цифра;
  буквы-двойники OCR в числах (О→0, З→3, l→1) исправляются перед поиском.
- **Телефоны** — +7/8/7 и 10–11 цифр в типичных форматах, в т.ч. с 4-значным кодом города `8 (7162) 32-31-34`; после «тел./phone/моб.».
- **E-mail** — и с пробелами вокруг `@` или `©` вместо него (ошибки OCR).
- **Номера** — после №, No, N°, #, ID, серия, рег., регистрац…, тіркеу, нөмір, номер, Certificate ID, Credential ID, Verify, код;
  отдельные числа от 6 цифр (не годы и не даты, даже если OCR потерял точку: `14.032025`); токены от 8 символов из букв
  и цифр (`7XQ2M9K4PLWB`); ссылки проверки с id документа (`…/verify/7XQ2…`; общая страница `site.ru/check/` не в счёт).
- **Даты рождения** — после «дата рождения», «туған», «born», «д.р.» (в той же или следующей строке) и перед «года рождения», «г.р.», «жылы туған».
- **Адреса** — ячейка с «ул.», «улица», «көшесі» (и OCR-вариантами «кешесі»), «пр.», «проспект», «мкр», «кв.», «дом», «N үй», «address», «street» и номером.
  Адреса и индексы организаций (бланки вузов) тоже попадают в кандидаты — их можно не закрашивать.
- **Оценки** — строка целиком: GPA, балл, оценк…, баға, score, grade с числом; строки транскрипта (буквенная оценка
  или 3,67 + числа по ячейкам); столбец под заголовком «Grade/Оценка»; ряд из одних небольших чисел (баллы навыков);
  «%» в таблицах, в коротких строках и рядом с «результат/итог» (не «скидка 20 % на курс»). Отдельно — баллы вида `49/100`.
- **QR** — jsQR на масштабах 1, ½, ¼ (и инверсия); найденный код закрашивается и поиск повторяется; рамка = код + 2 %.
- MRZ (`<<<`) удостоверений — строка целиком; заодно это подсказка «личный документ».

Рамки из текстового слоя PDF уже включают высоту шрифта (без запаса по вертикали), рамки OCR — с запасом;
`npm run media` добавляет ещё 0,4 %. Если рамка задевает соседнюю строку (название, уровень), сузь её по `--boxes`.

Правишь детектор (`scripts/lib/detect.mjs`) — добавь случай в `scripts/lib/detect.test.mjs` (только выдуманные
значения: файл публичный), прогони `node --test scripts/lib/detect.test.mjs`, затем `npm run sync -- --scan-only --all`
и посмотри review-картинки нескольких типичных документов.

Не ищет (смотри глазами): штрих-коды, рукописные номера и подписи, номера на печатях (текст по кругу OCR не читает),
номера на фото под углом, лица других людей, данные на фоне сложной графики. Уверенность < 0,6 — чаще всего ложное
срабатывание, но решать по картинке.

## 6. Типичные случаи

- **Скан-подборка на много страниц** — одна запись на страницу-ачивку: `source: [{ sha256, pages: "7" }]`,
  redact только этой страницы (`page: 7`), `--link <sha12> --entry <id> --pages 7`; лишние страницы — `--hide … --pages …`.
- **Один документ на двух страницах** — `pages: "1-2"`: публикуется первая; redact нужен для первой.
- **Дубли** (скан и фото одного диплома) — публикуем лучший, остальные `--hide … --reason duplicate --note "то же, что <id>"`.
- **Фото документа на столе** — `crop` по краям листа; redact в координатах исходной страницы (до crop).
- **Транскрипт / credit transfer** — если ценность в самом факте (академическая мобильность), закрасить все строки с оценками;
  если документ — только оценки, `--reason grades`.
- **EF SET и другие тесты** — уровень (B1/C1) можно показывать, баллы (49/100, баллы навыков) — закрасить.
- **DOCX** — картинки нет: для публикации нужен скан/скриншот; иначе `not-achievement`/`ask`.
- **PPTX** — страница 1 = первая картинка в презентации; текст слайдов — в `draft.md`.
- **HEIC** — если sharp не читает, сказать Геннадию сконвертировать в JPG.
- **PDF с паролем** — сказать Геннадию сохранить копию без пароля.
- **Файл изменился** (пересохранили) — это новый SHA-256: sync покажет его новым, старый станет «нет в папке» в `--status`;
  переносим `source.sha256` в записи на новый хэш, старый — `--forget`.
